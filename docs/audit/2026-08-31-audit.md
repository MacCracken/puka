# puka P(-1) audit — 2026-08-31 (0.6.22)

First audit of this repo. Scope: the whole of `src/` (5,788 lines) read line-by-line, with the
untrusted-input boundaries read twice — `src/parser.cyr` (PTY bytes), `src/platform/wayland/client.cyr`
(compositor messages), `src/platform/setu/window_setu.cyr` (compositor messages), `src/input.cyr`
(paste payloads), `src/pty.cyr` (child spawn + environment).

Every finding below was **repaired in this release**, not just filed. Method was reading, not
tooling: `cyrius lint` reports 0 warnings across every file and found none of this.

## Severity

Nothing here is remotely exploitable by an unprivileged remote party — puka has no network surface.
"High" means *memory corruption reachable from data puka does not control* (child process output, or
a compositor). The threat model is the one the project states for itself: the parser eats adversarial
byte streams **by definition**, and a sovereign Wayland client that decodes the wire itself does not
get to assume the peer's framing is honest.

---

## HIGH

### A-01 — `grid_alt_screen`: a half-successful allocation poisons the guard, then writes to the null page

`src/grid.cyr`. The lazy backup buffers were allocated as:

```
if (grid_alt_g == 0) {
    grid_alt_g = alloc(n * 8);
    grid_alt_c = alloc(n * 8);
    if (grid_alt_g == 0) { return 0 - 1; }
    if (grid_alt_c == 0) { return 0 - 1; }
```

`grid_alt_g` is **published before** `grid_alt_c` is known to have succeeded, and `grid_alt_g == 0`
is the "not yet allocated" test. So if the first `alloc` succeeds and the second fails, the guard is
permanently poisoned: every later call skips the block entirely and runs the swap loop against
`grid_alt_c == 0` — `load64(0 + i * 8)` and `store64(0 + i * 8, …)` for all **69,120** cells.

**Reachable from untrusted PTY output.** `ESC[?1049h` is what vim, less, htop and tmux send on
startup, so any byte stream can request the alt screen at will; the `-1` return was discarded at all
four call sites in `terminal.cyr`, so the failed first attempt was silent.

**Fixed** — allocate into locals, publish both globals or neither.

### A-02 — `grid__sb_push`: the identical defect, on a far hotter path

`src/grid.cyr`. Same publish-before-verify shape for the scrollback ring. Reached by **ordinary
scrolling**, so nothing exotic has to happen for it to fire a second time and write a full row
through a null base pointer. **Fixed** the same way.

### A-03 — `client.cyr`: an unvalidated wire length → out-of-bounds read and information disclosure

`src/platform/wayland/client.cyr`, `wl_registry.global` handling. The interface-name length is a u32
read straight off the socket and was never tied to the message that carried it:

```
var L = wire_str_len(&wl_rbuf, o + 12);
var ver = load32(&wl_rbuf + wire_str_next(o + 12, L));   # index chosen by the peer
...
wl__emit(sp, L - 1);                                      # verbose mode
```

A `global` event declaring `L = 0xFFFFFFFF` makes the `ver` load a read roughly **4 GB past** an
8,192-byte buffer, and with `wl_verbose` on, `wl__emit(sp, L - 1)` writes that many bytes of puka's
own address space to stdout.

⭐ `wl__streq` was **already safe** and is the model the fix follows — it compares `strlen(lit)`
against `len` first, so a bogus length never reached its loop. The other two readers had no such
check. **Fixed** — `L` is validated against the message's own declared size before anything indexes
with it.

## MEDIUM

### A-04 — `wl__handle`: field reads not bounded by the message size

Every handler loaded at a fixed offset (`o + 8`, `o + 16`, `o + 20`) with nothing checking the
compositor actually sent that far. `wl__parse` bounds a message against the bytes *received*, which
is a different fact from "long enough to hold this field". A truncated 8-byte message carrying a key
opcode, arriving at the tail of a full `wl_rbuf`, read up to 16 bytes past the buffer.
**Fixed** — all field reads go through a size-checked `wl__u32`; a short field reads 0, which every
consumer already treats as absent.

### A-05 — unbounded per-keystroke heap leak in the event loop

`src/main.cyr` allocated its key scratch (`alloc(32)` twice) **inside** the loop body — 64 bytes
leaked per keystroke, permanently, because `alloc` has no `free`.

⛔ The file **states this exact rule 130 lines earlier**, for `puka_szpx`: *"Allocated ONCE — the loop
reads it every frame and `alloc` has no free, so a per-frame allocation would leak 16 B per present
for the life of the terminal."* The key path simply predated that idiom. Returns were also unchecked:
a failed `alloc` returned 0 and `win_next_key(0, 0)` would have stored through a null pointer.
**Fixed** — module-global scratch, minted once and checked.

### A-06 — `puka__say_num` leaked 48 bytes per call

`src/main.cyr`. Two `alloc(24)` calls per number printed. Not a cold path: the resize branch calls it
**six times per compositor configure**, and a window drag configures continuously.
**Fixed** — function-local stack buffers.

### A-07 — agnos `pty_pump` allocated 128 bytes per call, and it is called per frame

`src/pty.cyr`. `src/main.cyr` calls `pty_pump(2)` once per frame; the agnos arm allocated on every
one of those calls — roughly **7.7 KB/s at 60 fps**, unbounded for the life of the terminal. The
Linux arm directly above it already used a function-local `var buf[1024]`; this arm reached for the
heap for no reason the code gives. **Fixed** — stack buffer, matching the Linux arm.

## LOW

### A-08 — agnos `pty_open`: unchecked `alloc`, and a leak on re-open
A failed `alloc` returned 0 and `sys_chan_mint(0)` would have had the kernel write the fd pair
through a null pointer; `pty_open` can also legitimately repeat after a `pty_close`.
**Fixed** — a module-global static holds the pair.

### A-09 — three grid write paths had no row guard
`grid__copy_row`, `grid_insert_cells`, `grid_delete_cells` stride the backing store directly
(`r * GRID_MAX_COLS`) rather than going through `grid_set_cell`, and carried no bounds check on `r`.
Every *other* write path in the file checks. Safe only because all callers happen to pass the cursor
row — an invariant that was real and **written down nowhere**. **Fixed** — guarded; regression test
added.

### A-10 — the viewport accessors dropped the bounds checks their twins have
`grid__view_gword` / `grid__view_cword` had no range checks, while `grid_glyph` / `grid_fg` /
`grid_attr` / `grid_bg` all do. The renderer only ever passes display rows, which is why it never
fired. **Fixed** — guarded; regression test added.

### A-11 — `win_open` had no overflow backstop, unlike `win_resize_apply`
`src/platform/setu/window_setu.cyr`. The resize path validated its extent; the **open** path — which
takes cols/rows from the caller rather than from the grid's clamps — did not. A wrapped `nbytes`
allocates a small buffer the present then reads `win_w * win_h * 4` bytes out of. **Fixed.**

### A-12 — `utf8_feed` ate the byte that aborted a sequence
A byte that is not a continuation is not part of the sequence it interrupts — it starts the next
character. `E2 41` ("truncated 3-byte lead, then 'A'") yielded U+FFFD and **silently dropped the
'A'**. Documented in-code as a choice, but it loses real characters from any child that emits a
partial write. **Fixed** — the decoder flags the byte as unconsumed and `term_feed` re-dispatches it
once (provably once: the decoder is back in ground state). Matches Unicode 15 §3.9 maximal-subpart
practice. Tests added at both the decoder and terminal level.

### A-13 — `pty__build_child_env` published a truncated final variable
The entry pointer was recorded **before** scanning for its NUL, so an environment cut off by the
8,191-byte read cap handed the child a complete-looking `PATH=/usr/bin:/usr/lo…`. A child with a
silently shortened PATH or HOME misbehaves in ways that look like anything except a truncated
environment. **Fixed** — scan first, drop an unterminated tail. A missing variable fails loudly; a
corrupt one does not.

⚠ The caps themselves (8,191 bytes, 125 variables) are still silent and are **left alone
deliberately** — raising them is a BSS decision, not a correctness one.

## Documentation defects

### A-14 — `window_setu.cyr`'s header under-claimed its own module
It read *"Input over setu is a later bite … `win_poll_events` / `win_next_key` are present-parity
stubs for now"* — false for several releases. The file handles `SETU_CLOSE`, `SETU_CONFIGURE` and
`SETU_INPUT_KEY` with a full HID-usage→evdev translation. A header that under-claims invites someone
to re-implement a working seam. **Corrected.**

### A-15 — `docs/development/state.md` described mabda as a held-back dependency
It said *"`[deps.mabda]` deliberately held at 3.2.11"*. mabda was **removed**, not held back.
Corrected in 0.6.21; the README's matching claim ("two git deps: kashi 1.0.2 and mabda 3.2.11") was
corrected in the same release.

## Gates that were green while measuring nothing

Two of the P(-1) gates passed on empty harnesses. Both are the same failure: a claim of coverage that
does not exist, which is worse than no harness at all.

### A-16 — `tests/puka.fcyr` fuzzed nothing
`fuzz_main` was `if (len == 0) { return 0; } return 0;`. It printed `fuzz: ok` and passed, for the
module CLAUDE.md names as *the highest-priority audit target*. **Replaced** with a real harness
against `term_feed` (the whole untrusted path, not just `vt_feed`): 16 targeted adversarial sequences
(params at the 65535 clamp turned into grid indices, degenerate and inverted scroll regions,
alt-screen thrash, ESC storms, OSC overflow past `VT_STR_CAP`, truncated UTF-8 spanning an escape),
plus 400 rounds of fixed-seed pseudo-random and escape-biased noise — roughly **820,000 adversarial
bytes**, asserting grid invariants after each. **1,297 assertions, all passing, also under
`cyrius fuzz --poison`.** Deterministic by construction so a failure reproduces exactly.

⭐ **MUTATION-VERIFIED, because "the harness is real now" is exactly the claim that must not be taken
on trust.** Deleting the cursor-row clamp from `grid_cursor_set` — a two-line change, and precisely
the kind of regression a parser fuzzer exists to catch — turns the run red: **4 failures** across
both the targeted and the escape-noise sections (`cursor row never negative`, `cursor row inside the
grid`, `escape noise: cursor row in range`). The stub it replaced passed that same mutation in
silence, which is the whole point.

### A-17 — `tests/puka.bcyr` benchmarked an empty function
It timed `fn bench_noop(): i64 { return 0; }`. It could not have detected a parser rewritten to be
ten times slower. **Replaced** with five hot-path baselines — see *Performance* below.

## Performance

Baselines established (x86_64 Linux dev host, timer floor ~1.35 µs measured and subtracted):

| bench | before | after |
|---|---|---|
| `vt_feed` printable | 10 ns | 10 ns |
| `vt_feed` CSI SGR sequence (7 B) | 123 ns | 122 ns |
| `term_feed` printable (full pipeline) | 300 ns | **186 ns** |
| `grid_scroll_up` 1 line (+scrollback) | 10.29 µs | 10.24 µs |
| `fb_render` 80×24 all-dirty frame | 3.177 ms | **1.694 ms** |

Three optimizations, all provably safe rather than heuristic:

- **`char_width` ASCII early-out.** Every plain `'A'` walked ~15 range checks in `uc__zero_width` and
  ~15 more in `uc__wide` — thirty calls to `uc__in` — to reach the answer 1. The lowest zero-width
  entry is U+0300 and the lowest wide entry is U+1100, so nothing in `0x20..0x7E` can be either.
- **Damage bitset: shift/mask instead of divide/modulo**, and `grid_cursor_set` no longer marks the
  same row twice when the cursor stays on its line (the common case while typing). This runs three
  times per printed character.
- **`fb__fill_rect` clamps once per rectangle** instead of calling the per-pixel guarded `fb__plot`
  245,760 times per frame. ⛔ The safety property is unchanged — the clamp is the *same* clamp,
  hoisted — and `fb__plot` remains the guarded path for scattered glyph writes. Pinned by a new
  regression test covering negative origins, both-axis overruns, fully-off-screen and negative-extent
  rectangles.

⚠ `fb_render` at 1.7 ms is an **all-dirty upper bound**, not a per-frame cost — the damage bitset
means a keystroke repaints one row. It is still ~10% of a 60 fps budget on a full repaint, and the
remaining cost is the per-cell glyph blit. Not pursued here.

## Audited and found correct

Recorded because "we looked and it was fine" is a result, and re-auditing costs the same as auditing.

- **No command injection.** `pty_spawn` builds an explicit `argv` vector and calls `sys_execve`
  directly — never a shell string, and `sys_system` appears nowhere in the tree.
- **`input_paste` is properly hardened.** Every write is bounds-checked against `cap`, and the body
  strips both CSI introducers — 7-bit `ESC` (0x1B) and 8-bit C1 (0x9B) — so an adversarial paste
  cannot emit its own `ESC[201~` to break out of the bracket and run commands.
- **Parser buffer arithmetic is exact.** Params cap at 15 (`vt_params[16]`), intermediates at 2,
  and the OSC buffer fills to exactly 512 bytes (`vt_str_buf[64]` = 64 × u64). The per-parameter
  clamp at 65,535 is applied after the multiply, so `65535 * 10 + 9` cannot wrap an i64.
- **The palette decode cannot be walked off the end.** `SGR 38;5;65535` yields a token of 65,536;
  `fb__palette_rgb` clamps to 0..255, and the truecolor tag bit (0x1000000) is unreachable from a
  parameter the parser has already clamped.
- **UTF-8 validation is complete.** Overlong forms (via a per-length minimum), UTF-16 surrogates,
  `0xC0`/`0xC1`, `0xF5`–`0xFF` and anything past U+10FFFF are all rejected to U+FFFD.
- **`fb__plot` bounds-clamps every coordinate**, and `fb_init` / `fb_resize` carry `sz / 3 != w * h`
  overflow backstops with checked `alloc` returns.
- **Wayland message framing is sound.** `wl__parse` rejects `size < 8` and never dispatches a message
  extending past the bytes received. (The *fields inside* a message were the gap — A-03, A-04.)
- **`pty__build_child_env`'s NUL backstop is exactly in bounds**: `file_read(…, 8191)` into an
  8,192-byte buffer, terminator at index ≤ 8,191.
- **Grid coordinate clamping holds under adversarial params.** `grid_cursor_set`, `grid_set_scroll`,
  `grid_erase_cells`, `grid_insert_cells`, `grid_delete_cells` and the scroll primitives all clamp;
  a new fuzz section drives every one of them at the 65,535 parameter clamp.
- **No `unsafe`-equivalent escape hatches**: `cyrius vet` reports 14 dependencies, **0 untrusted,
  0 missing**.

## Not pursued (recorded, not silently dropped)

- **`fb_render`'s per-cell glyph blit** — the remaining ~1.7 ms. A structural change to the renderer,
  not an audit repair.
- **The environment caps** (8,191 bytes / 125 variables) remain silent — see A-13.
- **`wl_pointer` is not bound**, so the Wayland backend has no wheel to forward; `win_next_scroll`
  returns 0 there for ABI parity. The setu backend does forward it (setu 0.8.8 kind 12).
- **No runtime verification on agnos or under a live compositor.** Everything above is source-level
  review plus headless tests on the Linux dev host. The `--agnos` result is that it *compiles*.
