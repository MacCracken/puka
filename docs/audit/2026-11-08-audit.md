# puka P(-1) audit — 2026-11-08 (0.7.3)

A full line-by-line audit of `src/` and `programs/puka_term.cyr` at 0.7.2, and the repairs that followed.

## Method

- **Four independent reads**, one per subsystem: the VT parser and terminal; the grid and renderer; the
  compositor edge (Wayland and setu); the PTY, input and event loop. Each was given the code and the threat
  model, not suspicions, and was asked to reproduce its High and Medium findings.
- **Every finding was then re-checked here before it was repaired.** The compositor and PTY reproductions
  were rerun against the repaired code.
- **Expected VT behaviour was compared with a real terminal:** kitty 0.49's parser, driven headless, against
  puka's `term_feed`, on 134 byte streams. A dev-time check only; nothing from kitty is used or built.
- **Repairs have tests wherever a headless test can reach them, and each new test was shown to fail** with
  its repair removed. Two tests written for this audit passed with the bug present and were rewritten. The agnos
  arms and some out-of-memory paths were checked by reading.

## Medium

**VT semantics.** PT-01 intermediates ignored, so `CSI $ r` ran as DECSTBM. PT-02 `:` sub-parameters flattened,
so `4:3` meant underline plus italic. PT-03 mode lists read only the first entry, so terminfo's `cvvis` left the
cursor hidden. PT-04 the pending-wrap latch survived moves and edits. PT-05 DECSC saved position only. PT-06
`CSI 3 J` wiped the screen and kept the scrollback. PT-07 margins ignored by CUU, CUD, CNL, CPL, VPA and DECOM
CUP, and IL/DL outside the region. PT-08 (B-11) overwritten wide cells left orphan halves. PT-09 a partial UTF-8
sequence survived a control byte. PT-10 REP and CBT, both advertised by `TERM=xterm-256color`, had no dispatch,
so ncurses output lost cells.

**Rendering and memory.** B-03 codepoints went to kashi as CP437 cells, so all of Latin-1 drew the wrong glyph
and box-drawing was invisible. B-02, W-10 buffers grew to exactly the new size with an allocator that has no
free: one window drag consumed 480 MB for a 6 MB buffer. B-01, W-11, D-05 every present leaked 64 B (half
repaired; see Deferred). B-04 damage was keyed by live row but consumed as display row while scrolled back.
B-05, PT-19 the viewport was not bound to the primary screen. B-06 a height shrink cut off the cursor line.

**The compositor connection.** W-05 sends blocked forever once a compositor stopped reading. W-06 a send to a dead
compositor died of SIGPIPE. W-07, D-06 the Wayland socket was inherited by the shell and everything it runs.
W-09 object ids climbed without limit.

**The terminal loop.** W-08, D-03 a child that never stops writing (`yes`) held the loop forever: no repaint, no
Ctrl-C. D-04 no child-exit path, so a shell that exited left a dead window running. D-07 `main.cyr` resized fd 0,
puka's stdin, instead of the PTY, so the shell never learned its size. D-08 on agnos an arrow key typed `[A` into
the command. D-09 Ctrl masked every ASCII key: Ctrl+- sent CR and ran the typed line. D-10 no key repeat on Wayland (deferred).

## Differences from kitty, kept on purpose

`tests/vt_semantics.tcyr` pins these so nobody "fixes" them to match.

- **At a pending wrap**, kitty parks its cursor one past the margin, so `CSI K`, DCH and BS differ. puka follows
  xterm and Ghostty: the cursor is on the last column, EL erases that cell, and the wrap is cleared.
- **`CSI 3 J`** clears the scrollback only, as in xterm and Ghostty. kitty also clears the screen.
- **A marker mid-parameter, or a parameter after an intermediate,** ignores through the final byte, per the
  Williams table. kitty prints the rest.
- **ESC inside a CSI** aborts it and starts the next sequence.
- **`?47`** does not restore the cursor, as in xterm.
- **More than 16 SGR parameters:** puka keeps the first 16, kitty keeps more. Combining marks and ZWJ are not
  stored until 0.8.2.

## Withdrawn

**PT-17**, bytes >= 0x80 aborting an ESC or CSI. kitty handles them exactly as puka does.

## Audited and found correct

At 0.7.2, before the repairs.

- **Parser arithmetic:** `vt_nparams`, `vt_ninter` and `vt_str_len` are exact against their buffers, the parameter
  clamp cannot wrap, and every loop is bounded by a clamped value.
- **The Williams transitions** match, apart from the two deliberate deviations (`:` and C1).
- **Grid bounds** under every primitive, through all 49 pairs of 1x1, 1x480, 144x1, 144x480, 2x2, 143x479 and 24x80.
- **Wayland framing:** a short size closes, a long one waits, splits reassemble, and registry strings are bounded.
- **SCM_RIGHTS:** the keymap fd is not leaked, and the memfd is close-on-exec.
- **The spawn path:** no shell string, an explicit argv, and no allocation between fork and exec.
- **`cyrius fuzz --bounds` was not adopted** (A-21): `src/` has no typed arrays for it to guard.

## Not run

Anything on agnos or under a live compositor, and the GPU probes. Compositors were simulated over real sockets.
The agnos arms were reviewed by reading and compile, including the agnos `pty_pump` cap and child-exit path.
