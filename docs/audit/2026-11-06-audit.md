# puka P(-1) audit — 2026-11-06 (0.7.0)

The P(-1) sweep before the 0.7.0 minor, which moves the toolchain onto cyrius's 6.7 language line.

**Scope: a delta audit, not a second line-by-line read.** It covers what changed since the
[2026-08-31 audit](2026-08-31-audit.md) (0.6.22):

- the two `src/` files that changed since then, `src/platform/setu/window_setu.cyr` and
  `src/platform/gpu/gpu.cyr` (57 lines added);
- the move from cyrius 6.6.20 to 6.7.9, which can change what code means without failing the build;
- the dependency moves of 0.6.24, 0.6.26 and 0.7.0, by changelog and by code diff for 0.7.0.

Everything else in `src/` is unchanged since that audit and was not re-read.

## Severity

As in the 2026-08-31 audit: puka has no network surface, and "High" means memory corruption reachable
from data puka does not control. **Nothing High or Medium was found.**

## LOW

### A-18 — a compositor that dies after a partial frame reads as idle forever

`setu_client_poll_input` in setu (`lib/setu.cyr`, unchanged at 0.9.0). On EOF or an error it does:

```
if (len > 0) { return 0; }                   # error but bytes pending — drain first
return 0 - 6;                                # EOF / error
```

Draining is right while a whole frame is buffered. But `setu__inbuf_take` cannot finish a partial
frame, so `len` stays above 0, the function returns 0 on every later call, and -6 never arrives. puka's
`win_poll_events` therefore answers `WIN_EV_NONE` forever and the terminal keeps running against a
dead socket, holding its PTY child. This is the failure 0.6.25 fixed for the whole-frame case.

**Reproduced** with a scratch copy of `tests/window_setu.tcyr`: the peer sends 8 bytes and closes, and
`win_poll_events` still answers `WIN_EV_NONE` after 1,000 polls.

It takes a compositor that sends a short record, since `SOCK_SEQPACKET` delivers a well-formed frame
whole. The effect is a process that does not exit, not memory corruption.

**Not fixed.** puka cannot tell this case from idle, so the fix belongs in setu: on a terminal read
error, return -6 once no complete frame remains. Recorded in `state.md` under *Dep gaps*.

## Documentation defects

### A-19 — CLAUDE.md names `exec_vec`; the code does not use it

CLAUDE.md says the PTY child spawn uses `exec_vec`. `src/pty.cyr` calls `sys_fork`, `sys_setsid` and
`sys_execve(path, &argv, env)`. The property the rule protects holds: argv is explicit and no shell
string is involved. Left for the maintainer, since CLAUDE.md is theirs to change.

### A-20 — the `path` rule in the dependencies note stopped being true at cyrius 6.7.6

`docs/architecture/001-dependencies.md` said a live `path` wins over `tag`. From 6.7.6 a default build
builds the tag and `path` is used only in local mode. **Fixed** in this release.

## Gates that were green while measuring nothing

### A-21 — `cyrius fuzz --bounds` and `cyrius test --bounds` check nothing in puka

Both pass, and neither says anything about puka. The bounds-checked mode (cyrius 6.7.8) guards typed
arrays, `*T` subscripts and slices. `src/` has none of them: every buffer is an address read through
`load8` .. `load64`, with 0 typed arrays and 0 subscript sites. **Not adopted as a gate.** A green run
would claim a coverage that does not exist, as `tests/puka.fcyr` did before 0.6.22 (A-16).

## Audited and found correct

**Silent meaning changes in cyrius 6.7.0–6.7.9.** A build catches what 6.7 refuses, not what it
compiles with a new meaning. These were searched for with comments and string literals stripped, in
`src/`, `programs/`, `tests/` and `lib/dhancha.cyr`. dhancha is included because it has no tag on the
6.7 line, so nobody else has checked its bundle against these changes.

| shape | release | sites in puka | sites in dhancha 0.10.4 |
|---|---|---:|---:|
| a lone `!`, dropped by the lexer until then | 6.7.3 | 0 | 0 |
| `~` on a constant before a literal operator | 6.7.9 | 0 | 0 |
| unary `-` on a name | 6.7.9 | 0 | 0 |
| typed pointers (narrow `*p`, operator results, `&q`) | 6.7.8, 6.7.9 | 0 | 0 |
| structs, `impl`, `self` | 6.7.0, 6.7.9 | 0 | 0 |
| `bool` declarations | 6.7.3 | 0 | 0 |
| `f32` | 6.7.6 | 0 | 0 |
| `fncall7`, `fncall8` | 6.7.6 | 0 | 0 |
| the exec family | 6.7.9 | 0 | 0 |
| signed slices | 6.7.8 | 0 | 0 |

The scanner was checked first, because a run of zeros proves nothing by itself: a control file with
every shape was caught on all 13 checks, with no hit from comments or strings, and all 696 fns and
8,320 code lines survive the stripping. The one `println` in these trees takes a string literal
(6.7.6 changed how an integer prints). The same scan found no site in the five other dependency
bundles, whose repos each report their own audit.

**Behaviour across the toolchain move.** The same scratch oracle, built on each toolchain, drives
`term_feed` with 9 targeted streams and 60 fixed-seed noise streams, and hashes the grid, the RGB
buffer and the buffer out of dhancha's widget path. **0 of 207 hashes differ** between 0.6.26 on 6.6.20
and 0.7.0 on 6.7.9. Changing one input byte moves exactly the 3 hashes of that case, so it can fail.
It covers the engine and the present path only. It does not cover `src/pty.cyr`, or a window backend.

**`win_poll_events` mapping setu's -6 to `WIN_EV_CLOSE`.** setu 0.8.12 made -6 mean "timed out, the
connection is still open" on its deadline reads, which would close a healthy terminal if it reached
this path. It does not: `setu_client_poll_input` is a non-blocking `recvfrom`, -6 comes only from EOF
or a read error, and EAGAIN is idle.

**`pgpu__fail` and `pgpu_release` on a partial init.** Each resource is released only if it was
recorded, and an unmap of a VA whose map failed is harmless. The seam is still not in any entry point.

**The literal `syscall(1, …)`, 11 sites in `src/`.** Correct on every target: `SYS_WRITE` is 1 on x86_64
Linux and on agnos, and cycc translates it on aarch64, which was run under `qemu-aarch64`. The literal
CLAUDE.md forbids is 60, because agnos's `SYS_EXIT` is 0. `sys_write` would still read better.

**Signals in the shell child.** puka spawns through raw `sys_execve`, so cyrius 6.7.9's reset of signal
state in the exec family does not reach it, and anything ignored in puka would be inherited. Nothing is:
`src/` touches no signal, and `signal_ignore` is dead code in the built binary.

**The syscall surface.** The delta adds one call site, a `write`, to `window_setu.cyr`. No new syscall.

**Dependencies at 0.7.0.** With comments stripped, setu, kashi, rupa and rekha have no code change from
their 0.6.26 tags, and sadish changes only its version probe. dhancha is the same tag. Every git
dependency is pinned by commit, and `cyrius deps --locked` and `deps --verify` both pass.
